二、已经完成的功能

1. 项目基础环境
   - 后端使用 Java 17、Spring Boot 3.3.5、Maven、JdbcTemplate。
   - 已连接 MySQL 的 family_tree 数据库。
   - 数据库已设计用户、家族、家族用户关联、成员、成员关系等基础表。
   - 已有外键、唯一约束及部分字段检查约束。
   - 后端可以打包为 JAR 并在本地 8080 端口启动。
   - 提供健康检查接口，返回后端已启动的信息。
   - 数据库密码通过 DB_PASSWORD 环境变量传入。

2. 家族管理后端接口
   - 查询家族列表。
   - 新增家族：当前只接收并保存家族名称。
   - 修改家族：当前只修改名称。
   - 删除家族。
   - 家族名称必须是字符串、不能为空白、不能超过120个 Unicode 码点。
   - 修改或删除不存在的家族时返回404。
   - 数据库因关联记录阻止删除家族时，返回409和说明。
   - 已在开发过程中验证家族新增、改名、删除及有关联记录时拒绝删除。

3. 成员管理后端接口
   - 查询指定家族的成员列表。
   - 按姓名进行包含匹配搜索。
   - 根据家族编号和成员编号查询单个成员。
   - 新增成员。
   - 修改成员。
   - 删除成员。
   - 分页查询，支持 page、size 和 name 参数。
   - 分页返回 records、total、page、size。
   - 总数统计和当前页查询使用相同的姓名过滤条件。
   - 页码必须大于等于1，每页条数必须在1到100之间。
   - 姓名必须是字符串、不能为空白、不能超过120个 Unicode 码点。
   - 性别允许空值，非空时仅接受 MALE、FEMALE、UNKNOWN。
   - 新增成员及分页查询会检查家族是否存在。
   - 查询、修改、删除找不到对应成员时返回404。
   - 数据库因关联资料阻止删除成员时，代码会将异常转换为409。
   - 已验证新增、修改、删除、姓名搜索、分页及部分无效请求。

   当前成员新增和修改实际写入的业务字段：
   name、gender、generation、birth_place、biography。
   新增时另外写入所属 family_id；修改时不能通过此接口变更所属家族。

4. 亲属关系管理后端接口
   - 查询指定家族的关系列表。
   - 通过 JOIN 返回关系两端成员的编号和姓名。
   - 新增 PARENT_CHILD 类型的亲子关系。
   - 删除指定关系。
   - 必须提供双方成员编号，编号必须大于0。
   - 不允许父母和子女编号相同。
   - 检查两位成员是否都属于指定家族。
   - 检查相同方向、相同类型的亲子关系是否已存在。
   - 重复关系返回409；找不到关系或对应成员时返回404。
   - 已验证正常新增、同一人请求返回400、重复关系检查、删除及重复删除。
   - 已确认删除关系不会删除关系两端的成员资料。

5. Controller/Service 分层
   - FamilyController 负责接收 HTTP 请求、调用 Service、返回响应。
   - FamilyService 负责家族相关校验和数据库操作。
   - PersonService 负责成员相关校验、搜索、分页和数据库操作。
   - RelationService 负责关系相关校验和数据库操作。
   - Controller 已移除 JdbcTemplate 依赖。
   - 使用 @Service 和构造方法注入管理依赖。
   - Controller 中迁移后不再使用的旧校验方法已经清理。
   - SQL 当前直接放在 Service 中，尚未单独拆分数据访问层。

6. DTO 和请求参数校验
   - 新增亲子关系接口已使用 Java record DTO 接收请求。
   - 当前文件名：ParentChildRelationRequset.java。
   - DTO 字段为 parentPersonId 和 childPersonId。
   - 已引入 spring-boot-starter-validation。
   - 使用 @Valid 触发请求对象校验。
   - 使用 @NotNull 校验编号必填。
   - 使用 @Positive 校验编号大于0。
   - 已验证缺少子女编号及父母编号为负数时返回400和对应提示。
   - 同一人、成员归属、重复关系等业务检查保留在 Service 中。

7. 统一错误返回
   - ApiExceptionHandler 使用 @RestControllerAdvice。
   - 处理 ResponseStatusException：返回业务检查产生的状态码和原因。
   - 处理 MethodArgumentNotValidException：返回 DTO 校验错误。
   - 处理 HttpMessageNotReadableException：返回 JSON 解析或字段转换错误。
   - 以上三类错误返回统一字段：status、message。
   - 已验证编号为 "abc"、JSON 缺少结束大括号时返回400，提示：
     “请求体格式错误，请检查JSON格式和字段类型”。
   - DTO 多字段同时出错时，目前只返回其中一个字段的错误信息。

8. 前端基础对接
   - 已使用用户提供的 Vue 前端项目作为 frontend。
   - 已有 Vue Router、Pinia、Element Plus、Axios 等基础组件与依赖。
   - Vite 将 /api 请求代理到 http://localhost:8080。
   - Axios 的 baseURL 为 /api，并配置请求超时。
   - frontend/src/api/family.js 已封装家族、成员、关系及分页请求。
   - 响应拦截器能够读取后端直接返回的数据。
   - 错误拦截器读取 error.response.data.message，并显示 Element Plus 提示。
   - 已通过浏览器控制台验证部分查询、搜索和分页封装。
   - 已验证前端能够弹出“未找到该家族成员”等后端提示。
   - 保留了原项目的页面布局、登录页、注册页及导航基础。

六、当前已实现的接口清单

GET     /api/health

家族：
GET     /api/families
POST    /api/families
PUT     /api/families/{familyId}

成员：
GET     /api/families/{familyId}/persons
GET     /api/families/{familyId}/persons/{personId}

PUT     /api/families/{familyId}/persons/{personId}
DELETE  /api/families/{familyId}/persons/{personId}
GET     /api/families/{familyId}/persons/page

亲属关系：
GET     /api/families/{familyId}/relations
POST    /api/families/{familyId}/relations
DELETE  /api/families/{familyId}/relations/{relationId}
